# Сравнительный анализ: Наш SAST vs Bandit

## Тестовый кейс: `complex_test.py`
Код содержит межпроцедурную SQL-инъекцию, распределенную между методами класса `VulnerableApp`.

## Результаты Bandit
- ✅ Нашел `hashlib.md5` (Weak Crypto)
- ✅ Нашел `api_key` (Hardcoded Secret)
- ⚠️ **Пропустил/Низкая уверенность** в SQL Injection в методе `get_profile()`.
  - *Причина:* Bandit не отслеживает состояние `self.current_user` между методами `login()` и `get_profile()`. Он видит только строковую конкатенацию внутри одного метода.
- ⚠️ Выдал предупреждение на `os.system`, несмотря на санитайзер `int()`.

## Результаты Нашего Анализатора
- ✅ Нашел `hashlib.md5`
- ✅ Нашел `api_key`
- ✅ **Нашел SQL Injection (Critical)** в методе `get_profile()`.
  - *Преимущество:* Модуль `Class State Memory` успешно отследил tainted-данные из `login()` в `get_profile()`.
- ✅ Корректно обработал санитайзер `int()` в `os.system` (не стал генерировать ложное срабатывание для Command Injection, так как данные приведены к числу).

## Вывод
Наш анализатор превосходит Bandit в точности межпроцедурного анализа (OOP State Tracking) и контекстной обработке санитайзеров, оставаясь при этом открытым инструментом.
